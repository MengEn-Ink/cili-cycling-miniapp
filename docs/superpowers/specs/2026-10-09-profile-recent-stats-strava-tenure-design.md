# 个人中心近 90 天数据与 Strava 年限设计

## 背景

个人中心当前同时展示 Strava 累计骑行和近 90 天表现。累计里程、累计次数、移动时间和累计爬升信息密度较高，但不能直接反映骑手最近状态。产品希望个人中心聚焦近 90 天数据，并用简洁年限文案补充长期身份感。

骑行年限按 Strava 注册时间计算，不新增人工填写字段。由于该时间只能代表 Strava 账号年龄，页面不得将其描述为完整的现实骑龄。

## 目标

1. 个人中心不再展示 Strava 累计骑行指标，只展示近 90 天指标。
2. 根据 Strava 骑手资料的 `created_at` 计算完整周年数。
3. 在个人中心以准确、紧凑的文案展示 Strava 年限。
4. 现有用户在下一次 Strava 同步后自动补齐，无需重新授权。
5. 获取注册时间失败时不影响近 90 天同步、报名资格或既有数据展示。

## 非目标

- 不新增“开始骑行年份”或“骑行年限”个人资料字段。
- 不把小程序绑定 Strava 的时间当作 Strava 注册时间。
- 不移除 Strava Athlete Stats 的累计数据采集或底层兼容字段。
- 不修改独立骑行名片页、活动详情公开骑友卡或管理员审核卡的现有指标布局。
- 不根据当前 90 天活动窗口推断骑行年限。

## 数据来源

Strava 官方当前骑手接口 `GET /athlete` 返回骑手资料，其中 `created_at` 是 Strava 账号创建时间。同步流程新增可选的 `athlete` 请求，与 90 天活动窗口和累计统计并行执行。

注册时间必须满足：

- 可解析为有效 ISO 时间；
- 不晚于本次同步时间；
- 与当前凭证的骑手身份来自同一次授权上下文。

合法时间写入 `strava_snapshots.athlete_created_at`。字段为可选值，不新增集合或索引。

## 同步与降级

`GET /athlete` 是辅助请求，不属于报名就绪的必要条件：

- 请求成功且时间合法：写入新的 `athlete_created_at`；
- 请求失败或时间非法，但同一 `athlete_id` 的旧快照已有合法时间：保留旧值；
- 请求失败且没有旧值：省略字段；
- 90 天活动请求失败：仍按现有规则令同步失败；
- 累计 Athlete Stats 失败：继续按现有可选累计统计规则处理。

同步不得因为 Strava 注册时间缺失而改变 `ready`、`partial`、`failed` 等既有状态，也不得影响报名资格。

源代码只修改 `cloudfunctions/strava-shared`；通过 `npm run cloud:prepare` 同步到 `strava-auth` 和 `strava-callback` 的部署副本。

## 年限计算

客户端使用服务端返回的 `generated_at` 作为计算基准，避免设备时钟偏差。完整周年计算遵循公历月日边界：

- 已过当年注册周年：当前年份减注册年份；
- 未到当年注册周年：再减 1；
- 闰日注册账号在非闰年以 2 月 28 日作为周年边界；
- 结果为 0：显示“加入 STRAVA 未满 1 年”；
- 结果大于 0：显示“加入 STRAVA N 年”；
- 时间缺失或非法：不显示年限。

文案明确使用 `STRAVA`，不显示“骑行 N 年”，避免把平台账号年龄误解为现实骑龄。

## 服务端投影

个人能力名片接口在顶层新增可选字段：

```json
{
  "strava_joined_at": "2019-05-18T09:30:00.000Z"
}
```

只有凭证可用、快照属于当前 `athlete_id` 且时间合法时才返回。旧快照继续返回原有结构。

## 客户端模型

`PersonalCapabilityCard` 新增可选 `stravaJoinedAt`。仓库映射严格验证日期，非法值令响应按现有契约拒绝，不把任意文本传入页面。

`personalCardViewModel` 新增：

- `stravaTenureText: string`
- `hasStravaTenure: boolean`

累计指标和 `lifetimeMetrics` 继续保留，供独立骑行名片页兼容使用。

## 个人中心展示

个人中心能力卡调整为：

1. 保留 CILI 标识和 Strava 连接状态。
2. 状态区下方或同一头部信息区展示“加入 STRAVA N 年”。
3. 删除“STRAVA 累计骑行”标题及累计指标网格。
4. 保留“近 90 天表现”及五项现有指标：
   - 近 90 天里程；
   - 骑行次数；
   - 最长骑行；
   - 近 90 天累计爬升；
   - 加权均速。
5. 近 90 天指标全部缺失时展示既有诚实空态，即使累计指标存在也不能掩盖空态。
6. 统计范围继续展示，明确 90 天窗口是否完整。

年限是身份补充信息，不进入指标网格，避免与近 90 天数据混为同一统计口径。

## 兼容性

- 旧快照没有 `athlete_created_at` 时不显示年限。
- 旧客户端忽略新增服务端字段。
- 新客户端兼容旧服务端缺少字段。
- 账号重绑后只使用新 `athlete_id` 对应快照，不继承旧账号注册时间。
- 本次不修改累计字段，因此独立骑行名片页保持原样。

## 测试

### 云函数

- Strava API 客户端正确请求 `GET /athlete` 并携带 Bearer token。
- 同步成功写入合法 `athlete_created_at`。
- 辅助请求失败不阻断 90 天同步。
- 同一骑手辅助请求失败时保留旧注册时间。
- 骑手变化时不继承旧注册时间。
- 未来时间或非法时间不写入快照。
- 个人能力名片只投影当前骑手的合法注册时间。

### 客户端

- 仓库映射新增可选注册时间并拒绝非法日期。
- 周年前、周年当天、周年后和闰日边界计算正确。
- 未满一年显示“加入 STRAVA 未满 1 年”。
- 缺失时间时隐藏文案。
- 个人中心模板不包含累计指标循环或“STRAVA 累计骑行”。
- 独立骑行名片页仍保留累计指标。
- 近 90 天全部缺失时显示空态。

### 回归

- `npm run cloud:prepare && npm run validate`
- CloudBase 部署包一致性检查
- 真实测试环境同步后回读 `athlete_created_at`
- 个人中心验证年限文案和仅近 90 天指标
- 报名就绪状态及核心报名流程 smoke

## 部署

代码验证通过后部署：

1. `strava-auth`：同步流程和 Strava API 客户端变更；
2. `strava-callback`：保持由共享 OAuth 源生成的部署副本一致；
3. `profile`：个人能力名片新增注册时间投影；
4. 微信开发版：个人中心展示变更。

部署后先执行无身份拒绝型 smoke，再用已连接 Strava 的测试身份触发真实同步。写操作超时必须先回读快照，不盲目重试。验证完成后确认报名资格未变化。
