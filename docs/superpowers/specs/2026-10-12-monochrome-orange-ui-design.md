# 黑白橙票据式 UI 收敛设计

## 目标

在不改变业务流程、状态机和页面文案的前提下，把界面颜色严格收敛为黑、白、灰阶与主题橙。用户上传的照片、活动封面和二维码属于内容资产，不做强制去色。

## 视觉规则

- 页面底色使用暖白，内容表面使用纯白；正文、强边框与主按钮使用近黑。
- 主题橙只承担品牌识别、当前选中、待处理提示和方向引导，不再混入绿、蓝、红、黄等状态色。
- 重点信息采用“黑底、白字、粗体”的票据栏表达；次级信息使用白底黑框或中性灰底。
- 状态差异依靠明确文案、边框、底色明暗和位置表达，不只依赖颜色。
- 用户照片和活动封面保留原色，叠加文字区域保持黑白高对比。

## 行程页设计

- 顶部状态统计改为整块黑色票根，数字与标签统一白色；待处理数字可用主题橙提示。
- 行程卡统一纯白底与近黑描边，取消审核通过的浅绿色卡面。
- 集合时间与集合地点是出发前最关键的信息，改为黑底白字的票据主栏，左侧使用橙色短线定位。
- 状态标签：可出发使用黑底白字，待处理使用橙色边框与浅橙底，失效状态使用灰底黑字。
- 删除记录仍保留明确文字与确认交互，但视觉改用黑白，不再依赖红色。

## 其他模块核对

- 活动首页：选中态和进度使用主题橙，其余卡片与筛选保持黑白。
- 活动详情与报名：主 CTA 使用黑底白字，主题橙用于路线箭头、当前步骤和待处理提示。
- 个人中心：照片区域允许保留内容原色；信息卡、状态和入口统一黑白橙。
- 设置、Strava 与管理页：成功、警告、失败统一通过文案与结构区分，避免绿色、蓝色和红色状态块。
- 公共状态标签统一由共享组件承载，页面不得自行引入新的状态色。

## 验收

1. 375×812 基线下，行程页不出现浅绿色、浅蓝色或浅红色卡片。
2. 集合时间、地点在首屏中形成最高信息权重，黑底白字对比满足可读性要求。
3. 公共 token 与状态标签只使用黑白灰和主题橙。
4. 状态文本、触控区、侧滑删除、凭证跳转与安全区行为保持不变。
5. iOS 与 Android 真机分别核对活动、行程、个人中心、设置和 Strava 页面。
