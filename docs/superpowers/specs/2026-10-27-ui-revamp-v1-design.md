# UI 改版 V1 设计规格

日期：2026-10-27。冻结基线：`origin/main@8fd0627616370fef81be7a550df44a571c154433`。当前状态：`DIRECTION_APPROVED / SPEC_REVIEW_PENDING / IMPLEMENTATION_NOT_STARTED`。

本规格承接已批准的全局方向：B「内容先行」作为全部 17 路由的统一设计语言；活动详情额外吸收 C「全宽摄影 + 上浮白色 sheet」；管理和表单页在 B 的 token、字阶、间距与组件体系内采用 A「稳健精修」的结构策略。本文件获 TraeX 审判者书面复核前，不修改产品 UI；复核通过后再进入 writing-plans 与分片 TDD。

## 目标与边界

本轮目标是在不改变产品能力的前提下，提高首屏信息到达速度、摄影内容可读性、跨页面层级一致性和实际触控可靠性，同时保留「骑有此里」现有的奶油纸感、品牌红、宋体大标题和真实骑行摄影。

明确不做：

- 不新增业务字段、数据源、假头像、假统计或空模块；页面只消费已有字段。
- 不改变报名、审批、凭证、隐私、Strava、俱乐部和管理员权限行为。
- 不把页面打开慢、云请求耗时或 runner 冷启动恢复混入视觉改版；性能另按稳定分段计时处理。
- 不内嵌新字体，不把参考图的蓝色、橙色或旅行产品信息架构变成品牌色与新功能。
- 不在一个 PR 完成整站换皮，不用 390 宽模拟器截图冻结视觉基线。
- 不改变仍待澄清的授权骑行卡片产品行为；该缺陷继续独立挂起。

## 已确认事实

- `app.json` 注册 6 条主包路由与 11 条分包路由，共 17 条运行路由。
- 当前页面 WXSS 在 `app.wxss` 之外有 4 处 hex 与 49 处 rgba，共 53 处颜色字面量；旧规格中的 46 rgba / 50 处总数作废。
- `components/activity-card/index.wxss` 还有一处硬编码字体族 `'Songti SC', STSong, serif`；页面和组件字体同样必须由主题契约管理。
- `package.json` 当前没有真实可执行的 `check:design`，`validate` 也不会执行该门禁。
- 活动首图当前固定 `lazy-load="{{true}}"`；本规格只允许首个可见活动卡改为 eager，其余图片继续 lazy，并要求同口径计时验证，不预先宣称性能提升。
- 现有 20 张真实云只读截图可证明对应 SHA 的功能可达，但包含个人信息且逻辑宽度为 390，只能私有巡检，不能公开归档或充当 Task 0 视觉基线。

## 方向裁决

### B：全局「内容先行」设计语言

B 不是活动首页的局部模板，而是 17 条路由共同消费的视觉体系：紧凑杂志刊头、轻量下划线分段、内容先于装饰、数值/单位分层、圆形方向按钮、稳定的摄影安全区以及更清晰的正文/辅助信息字重差。无摄影内容的设置、审批和表单页面不强行配图，改为用紧凑刊头、分组标题、弱容器、圆形方向入口与一致的统计/状态排版表达 B。

### 活动首页：B 的完整落点

首页使用紧凑杂志刊头、轻量下划线 tabs、4:3 摄影卡、标题安全区、圆形箭头和三栏统计。首张活动卡应在 iPhone X 375×812 逻辑视口的首屏内出现有效摄影内容与活动标题；首页不再让宣言占据约半屏。

原文案「每一次转弯，都有值得记住的风景。」不删除，迁移至「往期影像」无内容时的说明区；近期活动首页不重复展示。CTA 保留「查看活动」，落点仍为现有活动详情路由，不采用容易改变语义的「集合详情」。

右侧「共 N 场」只显示已有活动数组长度，不新增字段；它位于页面内容刊头而不是系统导航胶囊同一行，并按 `wx.getMenuButtonBoundingClientRect()` 的右侧保留区避让。拿不到胶囊信息时回退到 `32rpx` 内容右边距，不能覆盖或贴近微信胶囊。

### 活动详情：B + C「摄影封面 + 内容 sheet」

活动详情顶部为全宽摄影 hero，比例 4:3，底部圆角 `40rpx`；标题、日期和组织者置于安全区。首个摘要 sheet 左右边距 `24rpx`、圆角 `32rpx`、内容内边距 `32rpx`，向上覆盖 hero `48rpx`，高度由真实摘要内容决定，不固定成阻塞正文的整屏面板。

sheet 必须先显示已有摘要与关键统计，不等待 hero 图片解码，也不等待完整详情回源；完整路线、报名者、说明等继续按现有「先显摘要、完整回源」契约补齐。底部行动栏使用 `padding-bottom: env(safe-area-inset-bottom)`，CTA 和系统 Home Indicator 不重叠。

### 管理与表单：B + A「统一语言内的稳健精修」

管理和长表单保持现有信息架构、字段顺序和操作层级，以清晰扫描、错误提示和提交安全为优先，不引入无业务意义的沉浸大图；但必须使用 B 的紧凑刊头、字阶、间距、轻分段、圆形方向入口、数值/单位层级与命名 token，不能把「沿 A」理解为保留旧式裸样式。其余骑友页面直接按 B 的内容优先层级精修。

## 设计令牌契约

PR B 先完成表达层迁移，不改变任何视觉值。每个现存颜色字面量必须 1:1 映射到命名 token；随后路由族 UI PR 才能按本规格调整组件 token 的值。允许颜色字面量存在的位置只有 `app.wxss` 的 token 定义、`theme-contract.json` 及原生 JSON/TS 的契约源；页面和组件 WXSS 必须达到零 hex、零 `rgb()`、零 `rgba()`。

### 三层结构

| 层级 | 职责 | 冻结示例 |
| --- | --- | --- |
| primitive | 品牌原始色与透明度，不被页面直接消费 | paper `#fbf5ea`、ink `#211f1c`、brand `#e13b2b`、action `#c0321f` |
| semantic | 描述用途，承接跨页面一致性 | `--color-bg`、`--color-text`、`--color-text-muted`、`--color-border`、`--color-surface-raised` |
| component | 描述组件状态和叠层，不允许散落局部值 | `--scrim-cover-strong`、`--surface-sheet`、`--border-card`、`--shadow-sheet` |

### 色彩与叠层

| 角色 | 冻结值 | 用途与限制 |
| --- | --- | --- |
| paper / background | `#fbf5ea` | 页面底色，保持奶油纸感 |
| ink | `#211f1c` | 标题、主正文、选中胶囊 |
| muted | `#6f675d` | 辅助信息；在 paper/white 上需满足正文对比度 |
| brand | `#e13b2b` | 品牌强调、选中和主操作，禁止扩大成大面积背景 |
| action | `#c0321f` | 高对比行动文字与危险动作；不得与 brand 无理由互换 |
| raised | `#f3e6d0` | 骨架、无图与弱提示承托 |
| line | `#ededed` | 白色面上的弱分隔 |
| strong line | `#9a9186` | 需要更清晰边界的控件与可访问状态 |
| cover scrim top | `rgba(17, 15, 12, 0.04)` | 摄影顶部保留，不在页面中直接书写 |
| cover scrim strong | `rgba(17, 15, 12, 0.88)` | 摄影底部标题承托；以最亮真实照片验收 |
| hero scrim | `rgba(17, 15, 12, 0.72)` | 详情 hero 文案区域，不覆盖整张图的全部层次 |
| glass surface | `rgba(255, 255, 255, 0.88)` | 半透明圆钮；不支持模糊时回退纯白 |

PR B 必须把当前 53 处值全部按真实视觉语义命名并保值迁移；上表新增的 V1 组件值在相应 UI 分片引入，不得为了让 PR B 截图变化而提前套用。scrim 至少用仓库现有的 `lakeside.jpg` 等亮部面积最大的真实摄影样本验证白字；`mountain.jpg` 单一样本不足以通过。

### 字体、字阶与换行

字体族只能消费 `--font-family-body`、`--font-family-editorial`、`--font-family-mono`。editorial 栈冻结为 `"Songti SC", STSong, "Noto Serif CJK SC", serif`；body 使用平台系统无衬线；本轮不下载或内嵌字体。

| 角色 | 字号 / 行高 | 字重 | 规则 |
| --- | --- | --- | --- |
| eyebrow | `22/32rpx` | 600 | mono，可用少量字距，不承载关键操作 |
| body | `28/44rpx` | 400 | 默认正文，不延续全局 600 |
| emphasized body / button | `28/44rpx` | 600–700 | 按钮、状态和关键信息 |
| section title | `36/48rpx` | 600 | editorial，最多两行 |
| activity card title | `52/64rpx` | 600 | editorial，中英混排共享基线，最多两行 |
| compact page masthead | `56/64rpx` | 600 | editorial，首页短标题最多两行 |
| detail hero title | `64/76rpx` | 600 | editorial，最多两行，不能覆盖 CTA |
| stat value | `48/60rpx` | 700 | `font-variant-numeric: tabular-nums` |
| stat unit | `20/28rpx` | 500 | 与数值分层，不和数值等重 |

长数字优先缩短单位表达，不缩小到表中最小值以下；极端值允许统计单元内自然换行。活动标题最多两行并按字素边界截断，俱乐部名和集合点最多一行省略；「黑分解 ride」等中英混排不拆散 Latin 单词。关键正文、按钮和错误信息禁止省略。

Android 不保证存在 `Songti SC`/STSong；依次回退到可用的 Noto CJK serif 与系统 serif。本轮不内嵌字体，Task 0 必须加入 Android 的首页、详情、长中英标题截图，核对字重、行高、换行和裁切。若后续提议内嵌字体，需独立审批并给出字体文件、子集策略、主包增量和弱网加载预算。

### 间距、圆角与命中区

- 间距仅使用 `8/12/16/20/24/32/40/48rpx` 刻度；页面水平 gutter 为 `32rpx`，摄影 hero 的明确 edge-to-edge 例外写在组件契约中。
- 活动列表卡间距从当前 `48rpx` 收到 `32rpx`；正文卡圆角 `24rpx`，sheet `32rpx`，详情 hero 底部 `40rpx`。
- tabs、菜单、圆形箭头、底部 tabBar、CTA 与表单控件的逻辑命中区均不小于 `44×44px`（即标准 DPR 下 `88×88rpx` 的布局语义）；图标可小于命中区，但不可缩小点击容器。
- 相邻可点击区域至少相隔 `8px`（`16rpx`）；不可只靠透明覆盖层让命中区互相重叠。
- 浅色文字、边框和禁用态必须在目标背景上可读；正常正文按 WCAG 4.5:1、24px 以上大字按 3:1 做辅助核对，最终以微信真机截图与可操作性验收为准。

## 摄影媒体四态

所有包含封面的页面必须有四种可验状态，且容器比例在状态切换时不跳动：

1. 已加载：真实图片 + 对应 scrim + 标题安全区；
2. 加载中：同尺寸 raised 骨架，保留活动状态和文字摘要，不显示空白白块；
3. 无封面：奶油/raised 降级面、品牌化纹理或现有安全占位，文字改用 ink，不伪造摄影；
4. 加载失败：与无封面同结构并给出非阻塞重试入口；详情摘要和主操作仍可使用。

活动首页只对首个可见活动封面设置 eager，其余继续 lazy；列表排序、返回复用和往期影像切换不得导致所有图片同时 eager。验收记录同一环境下 `reLaunch → 首卡媒体状态稳定` 的修前/修后时间，但它只是首屏策略证据，不等于产品性能结论。

## 证据链与 Task 0

方向稿归档在 `docs/designs/2026-10-27-ui-revamp-v1/`，只用于设计决策，不是实现截图、基线或真机证据。真实云原始截图含个人信息，只保留在私有证据目录；公开材料必须遮蔽姓名、电话、OpenID、云资源标识和可识别头像。

分片顺序固定：

1. PR B：主题契约、当前 53 处颜色字面量归零、字体族字面量归零，新增 `test:design` / `check:design` 并接入 `validate`；README 和验收手册命令同步。
2. PR C：在目标 macOS 主机执行 Task 0。逻辑目标为 iPhone X 375×812，PNG 物理尺寸必须读取 PNG header 实测；记录工具精确版本、哈希主机指纹、开始/结束 HEAD 与 porcelain。补充 Android 宋体和亮图 scrim 样本。
3. 路由族 UI 分片：首页 → 详情/路线 → 我的/名片/设置 → 报名/凭证 → 管理/表单。每片独立 PR、独立回滚，不跨片补业务。

Task 0 之前，Pages 三宽度和 390 模拟器只做布局/功能巡检。每个 UI PR 需要：

- TDD RED/GREEN、定向测试、`check:ui-sync -- --strict`、`check:governance`、`check:design` 与全量 `validate`；
- 17 路由改前/改后截图；未受视觉影响的路由也要有运行可达证据和明确 `NO_VISUAL_CHANGE_EXPECTED`，不能静默漏跑；
- 冻结 SHA、跑前/跑后 HEAD 与 porcelain、设备/SDK/DevTools 版本、数据状态与脱敏清单；
- PR CI 全绿，合入后 main CI 回读；开发版上传 receipt 绑定同一 SHA；

## 可访问性与交互守恒
