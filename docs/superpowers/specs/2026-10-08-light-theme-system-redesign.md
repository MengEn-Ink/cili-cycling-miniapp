# 浅色主题高对比视觉系统设计

## 背景

当前浅色主题已具备基础语义色和对比度测试，但页面级样式仍保留大量面向深色主题的固定颜色、局部覆盖和独立布局规则。真实页面验证显示：

- 次级文字、占位文本和部分描边按钮在浅色背景上辨识度不足；
- 个人中心“编辑资料”等操作存在文字与背景接近的问题；
- 日期、时间和长数值在窄屏信息行中换行杂乱；
- 标题、指标、按钮和导航的居中规则不一致；
- 不同页面的卡片圆角、阴影、边界和留白缺少统一约束。

本设计采用已确认的“方案 C：高对比留白”，统一全站浅色主题，保持深色主题和业务行为不变。

## 设计目标

1. 浅色主题正文、说明、占位文本、状态和操作均清晰可读。
2. 建立稳定的居中规则，避免所有元素机械居中或同类元素对齐不一致。
3. 活动、行程、个人中心、报名表单和管理页面使用同一套排版、边界和间距系统。
4. 在 320px 等效窄屏下，日期、数值、按钮和长文本不遮挡、不截断、不挤压相邻内容。
5. 保留 CILI 的黑、白、灰、橙品牌特征，橙色只承担重点提示和关键操作。

## 视觉方向

### 配色比例

- 60%：纯白基础面与内容留白；
- 30%：黑色正文、灰色说明、边界和层级结构；
- 10%：品牌橙，用于关键状态、当前导航和主要操作。

浅色主题语义角色：

| 角色 | 目标值 | 用途 |
| --- | --- | --- |
| 页面背景 | `#ffffff` | 页面基础面 |
| 内容表面 | `#ffffff` | 卡片、表单和固定操作区 |
| 次级表面 | `#f1f1ef` | 选中态、禁用态和轻分组 |
| 主要文字 | `#080808` | 标题、正文和主要数值 |
| 次级文字 | `#4f4f4c` | 说明、元数据和字段标签 |
| 普通边界 | `#bdbdb8` | 分隔线和非关键边框 |
| 强边界 | `#111111` | 表单、指标组和主要内容边界 |
| 品牌橙 | `#bd3f00` | 当前状态、强调信息和主操作 |
| 品牌橙按下态 | `#8e2e00` | 主操作反馈 |
| 品牌橙前景 | `#ffffff` | 橙色按钮文字 |

成功、警告和错误继续使用独立语义色，不能只依赖颜色传达状态。正文和占位文本对背景的对比度不低于 `4.5:1`，控件边界和图标不低于 `3:1`。

### 深色和影像区域

- 深色主题不随本次设计重做，只接受为共享组件兼容而产生的必要调整。
- 活动详情和个人名片的摄影 Hero 保持深色覆层和白色文字。
- Hero 下方立即回到浅色系统，不把黑色大面积扩散到普通内容区。

## 字体系统

使用微信小程序系统字体栈，不引入网络字体，避免加载和字形回退导致布局跳动。

| 角色 | 建议规格 | 对齐 |
| --- | --- | --- |
| 页面主标题 | `46rpx / 1.08 / 900` | 居中或按页面主轴左对齐 |
| 区块标题 | `32rpx / 1.25 / 900` | 左对齐 |
| 主要正文 | `28rpx / 1.55 / 600` | 左对齐 |
| 次级正文 | `25rpx / 1.5 / 500` | 左对齐 |
| 元数据与标签 | `22-24rpx / 1.4 / 700` | 随字段或指标对齐 |
| 关键数字 | `36-46rpx / 1.05 / 900` | 单元格居中 |

规则：

- 页面标题、主要按钮文字和指标数字使用明确的高字重；
- 不再使用多个接近的灰色字号制造弱层级；
- 日期、里程、爬升、速度和人数启用等宽数字；
- 字间距保持 `0`，仅英文 overline 保留正向宽字距；
- 产品界面字号使用固定 `rpx` 阶梯，不随视口连续缩放。

## 布局系统

### 页面主轴

- 标准页面左右间距为 `32rpx`，320px 等效窄屏降为 `24rpx`；
- 同一页面中的标题、卡片、信息行和操作区共享同一内容轴；
- 固定底部操作区与正文使用相同左右边界；
- 不使用卡片嵌套卡片，内部层级依靠分隔线、留白和字重建立。

### 居中规则

以下内容居中：

- 原生导航标题；
- 页面级单句标题；
- 指标单元格中的数字和单位；
- 主按钮文字、空状态和单选按钮文字；
- 头像、状态图标等独立视觉焦点。

以下内容不强制居中：

- 多行正文和说明；
- 日期、时间、路线、费用等键值信息；
- 表单标签、输入值和错误提示；
- 管理列表和审批明细。

### 信息行

日期和长值使用稳定双列布局：

- 标签列保持固定最小宽度；
- 值列使用 `minmax(0, 1fr)`；
- 值默认右对齐，长内容允许按语义换行；
- 时间日期使用等宽数字，不以省略号隐藏关键事实；
- 320px 等效窄屏允许日期拆为“日期 / 时间”两行。

### 卡片和边界

- 重复项目卡片圆角不超过 `8px` 等效值；
- 高对比信息组使用 `#111111` 边界；
- 普通分组使用 `#bdbdb8` 分隔线；
- 浅色主题减少阴影，以边界和留白表达层级；
- 禁止装饰性渐变、光晕和大面积品牌橙背景。

## 页面应用

### 活动列表

- 品牌栏、标题和活动卡共享页面主轴；
- 活动卡指标三等分并光学居中；
- 活动状态和 CTA 不与标题争夺空间；
- CTA 在窄屏下可独占一行，最小触控高度保持 `88rpx`。

### 活动详情

- 摄影 Hero 保持深色表现；
- Hero 下方指标使用强边界三列网格；
- 活动时间、路线和报名信息改为稳定双列信息行；
- 固定底部 CTA 使用品牌橙，文字居中且不被安全区挤压。

### 我的行程

- 行程卡使用黑色正文和明确状态边框；
- 日期使用品牌橙，其他元数据使用高对比灰；
- 卡片标题、状态和详情入口在窄屏下不互相挤压。

### 个人中心

- 影像名片保留深色覆层；
- 骑行指标按稳定列宽居中；
- “编辑资料”改为黑底白字的明确操作，不再使用低对比描边；
- 管理入口使用分隔行，不使用多层卡片。

### 表单与管理页

- 输入框使用白底、黑色强边界和可读占位文字；
- 标签、说明、错误和状态采用统一语义色；
- 单选和分段控件使用边界、字重和背景共同表达选中态；
- 表单主操作使用品牌橙，次操作使用黑色或白底强边界；
- 审批、活动编辑和设置页遵循同一表单与信息行规则。

## 组件与实现边界

本次实现优先调整全局语义 token 和共享原语，再收敛页面级覆盖：

1. 在 `app.wxss` 固化浅色主题 token、字体阶梯、间距和通用控件规则。
2. 统一 `.card`、`.btn`、`.secondary`、输入框、状态标签、指标和信息行。
3. 删除或替换普通浅色内容区中的固定深色主题颜色。
4. 仅在摄影 Hero、遮罩和明确的深色展示区域保留固定白色文字。
5. 不修改报名、审批、Strava、资料或活动领域逻辑。

## 状态与异常

- 加载、空、错误、禁用、成功和警告状态均需在浅色主题下验证；
- 禁用按钮必须同时通过颜色、边界和不可交互状态表达；
- 图片不可用时回退到纯白高对比布局，不遗留不可读白字；
- 文本增长、日期换行和缺失字段不能改变主要控件尺寸；
- 深色主题不得因共享原语调整出现对比度回退。

## 验证策略

### 自动化契约

- 为浅色 token、字体阶梯、控件高度、边界和对齐规则补充失败测试；
- 检查正文、占位文字、按钮、状态和边界的 WCAG 对比度；
- 扫描主题化页面，禁止普通内容区继续使用深色主题固定文字色；
- 锁定 320px 等效窄屏的网格折行和固定操作区空间。

### 视觉验证

使用微信开发者工具自动化截图验证：

- 活动列表、活动详情、我的行程、个人中心；
- 资料编辑、报名表单、Strava、设置；
- 活动管理、活动编辑、报名审批和审批详情；
- 常规手机宽度与 320px 等效窄屏；
- 有图、无图、空、错误、禁用和长日期状态。

重点检查文字遮挡、按钮文字居中、信息行换行、指标列宽、固定操作区和安全区。

### 门禁

- 聚焦主题测试通过；
- 全量 `npm run validate` 通过；
- 浅色与深色关键页面截图均无可见回退；
- 工作区不包含预览工具生成物。

## 验收标准

1. 浅色主题所有正文、说明、占位文字和按钮均清晰可读。
2. 页面标题、指标和主操作视觉居中；日期、表单和长文本按阅读方向对齐。
3. 个人中心“编辑资料”等现有低对比操作得到修复。
4. 日期和长数值在常规与窄屏下不遮挡、不截断。
5. 所有页面使用统一的白、黑灰、橙语义系统，橙色不被滥用。
6. 深色主题、业务行为、云函数和数据契约保持不变。
