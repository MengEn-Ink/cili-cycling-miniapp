## 产品入口与交互

### 设置

使用当前 `management-row` 列表，新增必要入口：

- “授权设置”：`open-type="openSetting"`，辅以微信右上角“…”的实际隐私删除路径说明；不称为一键撤销全部授权。
- “资料删除”：先读取处理状态、显示准确范围，再明确确认；取消不写云端；错误就地可重试；请求未完成时显示进度，不显示删除成功。
- “意见反馈与举报”：`open-type="feedback"`，附近说明可用于问题、内容举报和权利请求；后台收件由负责人实际处理。
- “联系与主体说明”：仅展示已核验的主体、隐私联系渠道和备案编号；资料未核验不得用示例值占位上架。

不新建路由；长说明按列表行下方或已有模态分层展示。清理缓存保持原有范围与文案；资料删除清理相关缓存，但不让用户误认为仅本地清理。

### 公开信息同意

展示规则保持：本人和审核管理员完整查看实名、电话；普通骑友不见实名、电话；司机电话按既有规则公开。

实现显著说明和独立同意操作，默认未同意，不用预勾选或普通“保存”替代：

- 昵称用于公开名单，头像/背景用于骑友展示和名片；明确范围、撤回入口以及他人已下载副本的限制。
- 公开照片是可选项；拒绝可选公开照片不能阻止必要报名或基本浏览，需同步当前头像必填和公开投影边界。
- 后援车司机信息由组织者取得司机本人同意，并留受控记录；组织者保存前确认已取得同意，记录实际公开字段、活动版本与时间，不能把组织者勾选当司机本人签名。
- 紧急联系人用途与告知/同意单列说明，不默认包含公开披露。

同意记录绑定可信用户、用途、政策版本与公开字段/媒体版本，客户端不可指定主体或直接写记录。旧同意不能覆盖更换图片或扩大公开范围。撤回后停止对应公开投影和新 URL 签发，保留必要本人/审核用途必须有独立依据。

## 资料删除领域

### 命名与范围

首版命名“资料删除”，不宣称注销微信账号或删除全部历史活动。默认清除本人 profile 可删除个人字段、报名快照的私人副本、本人个人头像/背景与对应上传意图。账号角色、俱乐部和已发布活动不按 owner 批量删除；必要身份关联和依法保留须说明。

复制、更正、特定字段撤回和因安全/法律原因存在限制的请求通过官方反馈及真实联系渠道受理。自助不能立即完成时仍受理并说明限制，不能无限期拒绝。

### 服务边界与数据

- `profile` 新增本人 `requestDeletion`、`deletionStatus` 动作；输入只含请求标识、已展示的确认范围和版本，不接受 owner、media IDs 或任意集合名。
- 新增 `privacy_requests`，客户端全拒绝。记录 `_id/owner_openid/kind/policy_version/generation/status/created_at/updated_at`、分阶段游标、重试时间、租约及非敏感错误分类，不保存姓名电话原值。
- 使用确定性用户+请求标识防重复；对同一未完成删除返回同一进度，完成请求不会在重试时删除用户后续明确创建的新资料。
- 以 `profiles` 的删除 generation/锁作为所有个人写入口读取的共同事务文档。`update`、头像、手机号、上传路径/finalize、报名提交和必要审核转换都检查锁；缺 profile 的旧请求不能绕过创建阶段的锁。
- 普通 `get` 不主动重建 profile；删除完成后再次创建资料必须是新的显式用户动作和适用同意，递增 generation。旧请求和旧媒体完成回调失效。
- 分批工作由专用 `privacy-maintenance` 定时云函数处理，调用者仅允许受配置的 Timer；引入集合、索引、定时器和云包全量命令同步。不得借用媒体 Timer 的客户端 action 执行任意删除。

任务状态为 `requested → processing → awaiting_media / restricted → completed`，暂时故障进入 `retryable` 并返回对应阶段，耗尽重试进入 `manual_review`。`restricted` 与 `manual_review` 不是完成，负责人须能从受控后台查询并处置。

### 进行中报名

自助确认前展示“删除资料会影响报名联络与凭证”。用户可先按原取消链路取消可取消报名；不直接改状态、占位数或候补。

存在未结束且无法简单取消的 `checked_in` 等报名、未决安全事项或法律保留时，请求进入受限处理。立即暂停非必要公开用途、清除不必要字段；必要现场联络字段仅按可说明的依据暂存，管理员核验后继续删除。不因为报名存在而拒绝受理；也不无提示删除现场必要联系方式。

报名提交与删除锁同事务校验；审批和候补恢复不得使用已删除资料或旧 profile snapshot。事件时间无法可信判定时不静默当已结束。

### 媒体与补偿

个人媒体仅限个人头像/背景及旧个人照片类别；owner 相同不意味着活动、俱乐部图片也属于本次删除范围。删除前扫描实际跨业务引用，先断开个人展示，再按既有 owner/canonical 校验建立清理任务。

复用现有 `profile-media-cleanup` 的租约和精确对象删除；不丢弃登记、先删存储再检查引用或清空全用户媒体。个人清理失败持久重试；任务查询待媒体全部进入可信删除终态才关闭。

针对已签发 URL，停止新签发与续签，记录最长剩余有效期，删除对象后回验原地址。不能承诺撤回他人已保存截图。后台和客户端缓存均失效；备份恢复按持久删除记录重放，避免 resurrect。

## Strava 撤销

复用 `strava-bridge` 增加可信本人 `disconnect`，不要把管理员资格丢失当作无法撤回的理由。撤销事务写入独立 generation/禁用状态，OAuth start、callback、refresh、import/save preview 全部核验，迟到 callback 不可写回 token。

第三方撤销调用和本地清除分开记录；失败时停止新导入并持久重试。不得先删除唯一凭证造成无法重试撤销；也不能长期保留可继续使用 token。只保留完成撤销所需的加密材料和受限状态，撤销后清除。本人可在 Strava 应用设置撤回，状态查询应处理已撤销情况。

已发布活动 GPX 是否继续使用按路线授权与请求范围判断；个人 token 撤销不自动删除公共活动或他人文件。当前 `read` scope、数据种类和适用跨境说明须在正式政策中如实体现。

## 内容安全和处置

### 文本

用独立共享模块封装 `cloud.openapi.security.msgSecCheck` v2，按照可公开字段白名单收集昵称、活动标题/说明和俱乐部公开介绍；不提交本人电话、实名或紧急联系人等无关字段。

字段校验和身份/权限校验在先；单次内容按官方 2500 字上限切分且保留字段边界。仅明确 `errcode=0` 且 `result.suggest=pass` 放行；risky/review/畸形/配额/权限/超时均不写公开新内容。审核失败的安全提示不回显原始命中词或私人原文。

文本检查在事务外，事务内验证归一化字段内容与审核摘要/版本一致，避免审核 A 保存 B、重试绕过或并发覆盖。管理员也执行同样检测；存量文本在发布前盘点处理。

### 图片

在现有媒体上传 canonical 协议上增加审核状态，保留原始归属、摘要和对象验证：

1. 先验证上传 intent 和 owner，再下载校验受限图片；WebP 不在官方 mediaCheckAsync 支持表中，采用可信服务端解码转 JPEG/PNG 后审核，并与最终 canonical 字节摘要绑定；不让客户端另传待审 URL。
2. 持久化 intent 和安全审核 generation，调用 v2，保存 trace 与确切摘要；请求受理成功不当 pass。
3. 使用专门 HTTP 回调云函数、消息推送网关路由及安全模式。检查签名、解密 AppID、消息类型、trace、generation；重复事件幂等，未知或过期事件不写业务资源。
4. 只有当前绑定明确 pass 允许媒体激活；pending/review/risky/retryable 均不返回可公开 URL，也不允许 activity/club 保存事务使用。
5. 客户端 finalize 返回“审核中”并有限刷新状态，旧合法图片保持显示；延迟与失败有持续状态和恢复动作，不把上传进度直接写成发布成功。
6. 图片审核结果改变、删除、版本替换或申诉均检查 generation；旧回调不复活新图或已删对象。

微信文档当前对“云函数接收消息推送”模式仅承诺客服消息，不假定 `wxa_media_check` 可以普通云调用触发。新增 HTTP 回调必须实际验证，token 和 AESKey 使用受控 Secret，入口不开客户端写权限。

### 下架与举报

使用官方反馈接收具体对象的举报，由平台管理员按权核验。活动复用已有下架状态转换、人数/凭证与通知规则，不扩大删除权限。头像、背景、昵称与俱乐部违规内容通过审核状态在服务端投影阻断；客户端缓存过期前需刷新/失效，已有地址按媒体策略处置。

保留受控处理记录、实际回复与申诉结果；不生成假客服消息。risky 内容不允许后台任意强制通过，合法更正需重新审核。

## UI 设计与验证

Intent：骑友从设置完成权益操作，得到实际进度和恢复方式。复用现有白色列表与中性说明，次动作不占用主行动红；删除在明确确认后触发，不铺整卡警告色。

Mapping：消费 `docs/design-contract.json`、`DESIGN.md` 和现有 `management-row`，保留大字号、中文正文 1.5 倍行高与至少 44px 实际触控范围。

Override：设置为长列表和简短进度；资料编辑增加同意说明与状态，活动编辑增加司机公开信息确认和图片审核状态。无新增路由、字段型业务功能或第二套主题。

反模式：清缓存当资料删除、打开反馈页当收件成功、自动勾选公开同意、异步受理当审核通过、错误隐藏却继续保存、把内部 fileID/Token/门禁词暴露给用户。

证据：正常、取消、拒绝、处理中、故障、受限、完成、长文案、窄屏和安全区；17 路由均绑定实际内容摘要及状态，真实图与敏感内容仅留私有临时路径。

## 实施顺序与验收

实施前审阅本设计；先写能复现缺失行为的测试再实现。

1. 隐私 contact/subject 配置与正式材料定稿；确定期限与合法保留依据。
2. 本人权益请求、锁和批次 worker：验证跨用户拒绝、重复请求、并发报名/更新/上传、快照回退、媒体失败、跨业务引用和备份恢复删除重放。
3. 公开同意与撤回：验证默认未同意、字段/图片版本绑定、拒绝可选图片仍可报名、司机授权记录及撤回投影。
4. Strava 撤销及 generation：验证刷新/回调竞争、权限丢失、撤销超时补偿、不重建 token、不误删活动 GPX。
5. 文本写入门禁与图片待审、回调：覆盖 risky/review/配额/畸形、验签/AppID/trace/重放、WebP 转换、旧图片保留、保存事务与公开 URL 阻断。
6. 设置与 Pages 对齐，隐私说明/授权/反馈/删除状态文案和真实运行证据；同步当前客户端版本和发布说明。
7. 全量 `validate`、`coverage`、设计、严格 UI 同步、治理与适用云包/审计；现有微信上传依赖告警单独保留，不扩例外掩盖。
8. GitHub Actions 部署受影响函数/集合/索引/网关/定时器和微信开发版；同 SHA 云环境回读，官方内容审核回调、反馈实际收件及普通成员双真机删除/报名旅程实测。

正式关闭条件是后台资料齐全、功能已部署并实际验收，不是本地测试或材料包编写完成。

## 审阅决策

需确认推荐的最小方案、资料删除范围与进行中报名处理、公开信息单独同意及撤回。主体、隐私联系渠道、具体保存/响应期限需要真实资料；这些缺口作为材料待核验状态，不以猜测值实现或上架。
