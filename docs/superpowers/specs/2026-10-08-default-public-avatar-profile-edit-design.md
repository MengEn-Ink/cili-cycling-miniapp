# 默认公开头像与资料编辑简化设计

## 目标

- 删除头像公开展示开关，所有已设置头像默认展示在活动报名骑友列表中。
- 让历史私密头像在功能上线后统一公开展示。
- 删除资料编辑页中的“展示身份 / 展示称号”区块。
- 保留头像文件来源、归属、版本和媒体完整性校验。

## 头像公开规则

### 统一展示

活动详情读取报名骑友时，只要用户资料存在有效头像，并通过现有 canonical 媒体校验，就返回可展示的临时头像 URL。

以下历史状态不再阻止头像展示：

- `avatar_visibility` 缺失；
- `avatar_visibility` 为 `private`；
- `avatar_visibility_revision` 与头像版本不一致。

这意味着已设置头像的历史用户会在功能上线后立即进入公开展示范围，不需要重新编辑资料或执行数据库迁移。

### 新头像

微信头像、自定义头像、CILI 主题头像和 Strava 导入头像在设置成功后均视为公开头像。服务端在头像版本更新时同步写入：

```text
avatar_visibility = public
avatar_visibility_revision = avatar_revision
```

客户端不再提供关闭入口。头像编辑区保留固定说明：“头像会展示在活动报名骑友列表中。”

### 安全边界

统一公开只移除用户可见性开关，不移除以下校验：

- 头像必须是服务端登记的云存储文件；
- 媒体记录必须属于当前用户且处于 active 状态；
- canonical 文件路径、来源类型、内容摘要和签名必须匹配；
- 公开接口只返回短期 HTTPS URL，不返回原始 file ID、openid 或其他私密字段；
- 任一安全校验失败时继续返回空头像，由客户端展示本地默认头像。

旧的可见性字段暂时保留在数据模型和响应兼容层中，避免扩大迁移范围；它们不再作为活动头像展示条件。

## 资料编辑页

- 删除“在活动骑手列表中展示头像”开关及相关提示。
- 删除 `onAvatarVisibilityChange` 交互和对应样式。
- 在头像选择区展示固定公开用途说明。
- 删除“展示身份”卡片及只读“展示称号”字段。
- 历史 `title` 数据和其他页面的只读展示暂时保留，不执行数据清理。
- 实名资料、紧急联系人、相册和头像选择能力保持不变。

## 实现范围

- 修改资料编辑页 WXML、WXSS 和页面逻辑。
- 修改头像设置与 Strava 头像导入的服务端写入语义。
- 修改活动公开读取的头像筛选规则。
- 更新客户端、云函数和静态契约测试。
- 同步设置页功能升级日志。

不新增数据库迁移脚本，不修改头像上传路径，不改变报名数据结构。

## 验收标准

- 资料编辑页不再出现头像展示开关、展示身份或展示称号。
- 头像区域明确说明头像会用于活动报名骑友列表。
- 新设置的任意来源头像自动保存为当前版本公开。
- 历史 `private`、缺少可见性字段或版本不一致的有效头像均可展示。
- 非法来源、非本人、非 active、伪造 canonical 或无法签发的头像仍不展示。
- 活动详情继续在真实头像不可用时显示本地 CILI 默认头像。
- 全量前端、云函数、安全契约和构建门禁通过。
