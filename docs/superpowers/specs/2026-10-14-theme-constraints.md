## 0. 为什么单独成文

- 主题约束要同时管产品代码、原型和以后的设计稿，生命周期比一次改版长；放在改版说明里，下次改版会被连带改写。
- 旧的三份主题文档（10-08 / 10-10 / 10-12）口径互相矛盾，需要一个独立文件明确“以哪条为准”（见 §9），并让旧文档顶部指向它。
- 改版说明只保留逐页方案、问题对照和开发分批，通过 `§` 编号引用本文，避免两处各写一份。

## 1. 主题与总原则

1. **只有一个明亮主题**。不恢复深色主题，不保留 `theme-dark` / `theme-light`，也不做运行时切换。
2. **黑白灰为主，橙色是信号**。颜色以黑、白、灰阶和主题橙为主；另允许**小范围**使用独立的成功色和警告色（只限 §3.3 列出的状态提示、提醒、小标签和小图标）。用户照片、活动封面、二维码属于内容资产，保留原色。
3. **层级靠结构表达，不靠颜色**。层级通过黑底信息条、2px 描边卡片、字号和字重区分，不靠状态色区分层级；成功色、警告色只表达“结果 / 提醒”，不表达层级。蓝色、红色仍禁止。
4. **可见即可操作**。所有可点元素必须是按钮（主、次、文字三类），或带“›”的整行。输入框都要有描边。
5. **不写死颜色**。页面样式里不出现 hex、rgb 字面量，统一使用 app.wxss 变量（见 §2；成功 / 警告色在进入 app.wxss 前以 §2.3 为准）。

### 2.2 禁止

- 任何写死的色值，包括 `#ff5722`、米黄底、浅蓝、浅红卡面、大面积浅绿底，以及 `navy`、`blue`。
- 原型 `docs/styles.css` 里出现 app.wxss 没有声明的颜色。原型变量必须与 app.wxss 同名同值，由契约测试检查。唯一例外是 §2.3 的四个“原型先行”变量，契约测试按本文色值检查。
- 新增颜色变量。确需新增时，先改 app.wxss 并更新本文（§2.3 是用户已批准的新增，进入 app.wxss 的时间见下）。

### 2.3 成功色与警告色（用户 2026-10-14 批准，小范围使用）

| 变量 | 色值 | 色相 | 用途 |
| --- | --- | --- | --- |
| `--color-status-success` | `#1d7a3e`（深绿） | 141° | 成功类文字、✓ 图标、成功小标签的字和 1px 描边 |
| `--color-status-success-soft` | `#e7f4eb` | — | 只作成功小标签、行内成功提示的底 |
| `--color-status-warning` | `#7a5c00`（深琥珀） | 45° | 提醒类文字、⚠ 图标、提醒小标签的字和 1px 描边 |
| `--color-status-warning-soft` | `#fbf1cc` | — | 只作提醒小标签、行内提醒的底 |

- **命名**：用 `--color-status-*`，不复用 app.wxss 里已有的 `--color-success` / `--color-warning`。那两个是黑和橙的历史别名，已被状态胶囊、凭证页等十余处引用，直接改值会让这些地方一起变色。
- **落地时间**：目前只在本文和原型 `docs/styles.css` 中定义。开发第 1 批“公共组件样式”时加入 app.wxss（同名同值），再把历史别名逐处替换为直接变量或新变量。本原型 PR 不改产品代码。
- **为什么是这两个色值**：两者在三种浅色底上都 ≥ 4.5:1（见 §6.1）。警告色色相 45°（琥珀黄褐），主题橙为 14°，相差 31°，而且明度低得多（6.25:1 对 3.52:1），并排时一眼能分清；同时文字形态不同：警告用“⚠ + 深琥珀字”，待处理用“橙描边 + 近黑字”。

## 3. 橙色的使用范围

### 3.1 只允许用在三类场景

| 场景 | 写法 |
| --- | --- |
| 当前步骤 | 步骤条当前格：`--color-brand` 底，`--color-on-brand` 字 |
| 选中、焦点 | 输入框聚焦描边；黑底信息条左侧 4px 短线（标记“当前这一条”） |
| 待处理 | 待审核数 > 0 的 8px 方点；“待审核 / 必填”徽标的 2px 橙描边；必填未完成或校验错误的输入框描边；错误类 toast 前的“!”；待处理提示条左侧 4px 竖线 |

例外：品牌 Logo 内的橙色（`--color-logo-accent`）不受此限制。

### 3.2 禁止用法

- 装饰圆环、进度环、曲线、三角、橙色描边卡片，以及橙色下划线装饰。
- 任何渐变（`linear-gradient` / `radial-gradient`）、光晕。
- 浅橙底（`--color-brand-soft` / `--color-warning-soft`）用作计数底、标签底、提示条底或卡片底。这两个变量只能用于输入框聚焦外发光。
- 大面积橙底：主按钮、底部栏、横幅一律不用橙底。主按钮是黑底。
- 橙色文字（`--color-brand` 在白底只有 3.52:1）。需要强调的文字用近黑加粗。
- 选中态、日期筛选、分段控件用橙色，这些状态用黑底白字。“已通过”用成功小标签（§3.3）。

### 3.3 成功色、警告色的使用范围

| 可以用 | 例子 |
| --- | --- |
| 状态提示（结果） | “已通过”小标签；复制成功、保存成功、发布成功的行内提示和 toast 前缀“✓” |
| 提醒（还没出问题，但要注意） | “即将截止”“名额紧张”“二维码可能过期”小标签或行内提醒 |
| 小标签、小图标 | 高 24–28px 的标签；14–16px 的 ✓ / ⚠ 图标 |

| 不能用 | 改用 |
| --- | --- |
| 大面积底色（卡片底、提示条底、横幅、页面区块） | 白底或 `--color-raised` |
| 按钮底色（含“通过”按钮） | 主按钮黑底 |
| 装饰（线条、圆环、插画、分隔线） | 近黑或 `--color-border` |
| 卡片描边、输入框描边 | 近黑；错误或待处理用橙 |

与橙色的分工：

| 含义 | 颜色 | 写法 |
| --- | --- | --- |
| **待处理**（要有人去做：待审核、必填、校验错误） | 主题橙 | 2px 橙描边 / 8px 橙方点 / 橙“!”，文字近黑 |
| **提醒**（时间或名额相关的风险） | 警告色 | 警告浅底 + 1px 警告描边 + “⚠” + 警告色文字 |
| **成功**（已经完成的结果） | 成功色 | 成功浅底 + 1px 成功描边 + “✓” + 成功色文字 |

- 同一张卡片里最多出现一个成功或警告标签；整页同类提醒不超过 3 处。
- 失败、错误不新增红色，仍按 §3.1 用橙色“!”与 `--color-brand-active` 文字。

## 4. 字号、字重、行高

基准画布 375px 宽，1px = 2rpx。

| 级别 | px | rpx | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- | --- |
| L1 | 24 | 48 | 32px（64rpx） | 900 | 页面主标题、关键大数字 |
| L2 | 18 | 36 | 26px（52rpx） | 800 | 卡片标题、信息条标题、数据格数字 |
| L3 | 14 | 28 | 22px（44rpx） | 正文 400，值、按钮、标签名 700–800 | 正文、按钮、标签—值、输入值 |
| L4 | 12 | 24 | 18px（36rpx） | 400，徽标 800 | 说明、徽标、计数、时间 |

- 只用这四级。现有 23 / 25 / 22 / 32 / 34 / 46rpx 等非标字号在开发批次中逐步收敛。
- 数字统一 `font-variant-numeric: tabular-nums`。版本号、凭证编号可以用等宽字体。
- 不用斜体，不用随视口变化的字号。字距为 0，品牌短标识除外。

## 6. 对比度（浅色主题）

### 6.1 最低标准

- 文字（含占位符、禁用文字）对其背景 ≥ **4.5:1**（WCAG 2.1 AA）。
- 非文字元素（控件描边、图标、焦点描边、方点）≥ 3:1。
- 下表由 app.wxss 色值计算。原型总览页会读取 CSS 变量实时复算。

| 前景 | 背景 | 比值 | 结论 |
| --- | --- | --- | --- |
| text `#171717` | surface / bg / raised | 17.93 / 16.14 / 15.16 | 通过 |
| muted `#666666` | surface / bg / raised | 5.74 / 5.17 / 4.85 | 通过 |
| subtle、placeholder `#737373` | surface | 4.74 | 通过 |
| on-action `#ffffff` | action `#171717` | 17.93 | 通过 |
| media-muted `#d4d4d4` | media-card-bg `#171717` | 12.09 | 通过 |
| on-brand `#171717` | brand `#e85b32` | 5.10 | 通过（步骤条当前格） |
| brand-active `#c84320` | surface | 4.91 | 通过（错误说明） |
| disabled-text `#666666` | raised | 4.85 | 通过（禁用按钮仍可读） |
| brand `#e85b32` | surface / bg | 3.52 / 3.16 | 只用于非文字元素 |
| border `#d6d6d2` | surface | 1.46 | 只作分隔线，不作交互控件描边 |
| status-success `#1d7a3e` | surface / bg / raised | 5.38 / 4.84 / 4.55 | 通过 |
| status-success `#1d7a3e` | status-success-soft `#e7f4eb` | 4.75 | 通过（成功小标签） |
| status-warning `#7a5c00` | surface / bg / raised | 6.25 / 5.63 / 5.29 | 通过 |
| status-warning `#7a5c00` | status-warning-soft `#fbf1cc` | 5.53 | 通过（提醒小标签） |
| text `#171717` | success-soft / warning-soft | 15.83 / 15.84 | 通过 |
| status-success / status-warning | overlay 上的 toast 前缀 | — | toast 底为黑色遮罩，前缀图标改用 `--color-on-action` 白色 ✓ / ⚠，不用状态色 |

### 6.2 两个低于标准的文字组合（限定用法）

| 组合 | 比值 | 限定 |
| --- | --- | --- |
| `--color-subtle` / `--color-placeholder` `#737373` 放在 `--color-bg` `#f3f3f1` 上 | 4.27 | 只能放在白底（surface、输入框）上；放在 `--color-raised` 灰底上更低（4.01），同样禁止。页面底或灰底上的弱文字改用 `--color-muted` |
| `--color-brand-active` `#c84320` 放在 `--color-bg` `#f3f3f1` 上 | 4.42 | 错误说明只能放在白底卡片或输入框下方，不能直接放在页面底或灰底上 |

## 7. 公共组件写法

| 组件 | 规范 |
| --- | --- |
| **卡片** | `--color-surface` 底，2px `--color-card-border` 描边，16rpx 圆角，内边距 32rpx，卡片间距 32rpx。卡片头为两位编号 + L2 标题 + 右侧徽标。**不在卡片里再套卡片**，二级信息用标签—值行或数据格。层级不靠阴影 |
| **主按钮** | `--color-action` 底，`--color-on-action` 字，88rpx 高，16rpx 圆角，L3 800。每屏最多一个，例如提交报名、发布活动、保存资料、通过 |
| **次按钮** | 白底，2px `--color-border-strong` 描边，近黑字，88rpx。卡片内小号次按钮为 72rpx |
| **文字按钮** | 近黑字加下划线，热区 ≥ 88rpx。用于删除、移除等低频操作。不允许没有下划线和热区的纯文字按钮 |
| **反白按钮** | 黑底信息条内的白底黑字按钮，内容 flex 居中，例如地图导航 |
| **按钮状态** | 按下用 `--color-action-active`。禁用为 `--color-raised` 底 + `--color-disabled-text` 字，不靠降透明度表示。加载时文字改为“提交中…”，按钮宽度不变 |
| **输入框** | 88rpx 高（多行 176rpx），白底，2px `--color-border-strong` 描边，16rpx 圆角，值 L3 700，占位符 `--color-placeholder`。**聚焦**：`--color-brand` 描边 + 2px `--color-brand-soft` 外发光。**错误**：`--color-brand` 描边，下方 L4 `--color-brand-active` 错误说明。**只读**：`--color-border` 描边 + `--color-raised` 底。日期、时间、集合方式用选择器（右侧“›”），不手填 ISO 时间。单行长文本超出时省略 |
| **上传控件** | 2px 虚线近黑描边白底块，文字为“+ 上传 GPX”等，最小 88rpx。缩略图三格 1:1 `cover`，首张带“封面”灰标签，右上为 44px 删除圆钮。**上传中**：`--color-overlay` 蒙层 + 白色百分比 + 进度条。**失败**：灰底 + “重新上传”文字按钮。计数用灰底，如“1 / 3” |
| **标签 / 徽标** | 高 24–28px，L4 800，圆角 4px。六种样式：solid（黑底白字，表示报名中、已上线、已解析、最新）、pending（白底 2px 橙描边近黑字，表示待审核、必填）、neutral（`--color-raised` 底，表示默认、封面、已结束、名额已满、候补、已取消、未通过）、outline（白底近黑描边，表示已下架、官方、GPX）、success（成功浅底 + 1px 成功描边 + “✓ ”前缀成功色字，只表示已通过、已复制、已保存）、warning（警告浅底 + 1px 警告描边 + “⚠ ”前缀警告色字，只表示即将截止、名额紧张、可能过期）。success / warning 不用于按钮和卡片头的主状态以外的装饰 |
| **分段控件 / 筛选** | 80rpx 高，2px 近黑外框，选中黑底白字，未选白底。日期筛选为双行票据标签，同样不用橙色 |
| **三格步骤条** | 三格等宽，2px 近黑外框。已完成格为“✓ 文字”，当前格为橙底近黑字 + 两位编号，未到格为 `--color-muted` 字。只用于填写报名链路 |
| **黑底信息条** | `--color-action` 底，白字，左侧 4px `--color-brand` 短线，16rpx 圆角。内容依次为徽标（白描边）、L2 标题、L4 `--color-media-muted` 时间和地点 |
| **标签—值行列表** | 每行 ≥ 88rpx，左侧标签 `--color-muted` L3，右侧值 `--color-text` L3 700 右对齐，行间 1px `--color-border`。可点行在右侧加“›”，整行可点 |
| **数据格** | 1px `--color-border` 分格，数字 L2 900 tabular-nums，标签 L4 muted。长值独占整行并 `nowrap` |

## 8. 交互约束

1. **不跳转第三方**。小程序内不出现打开、查看或跳转第三方网页的入口，也不使用 `web-view`。Strava 路线**只能复制链接**：调用 `wx.setClipboardData`，成功 toast“路线链接已复制”，失败 toast“复制失败，请稍后重试”。创建或编辑活动时，Strava 链接只做填写和解析，不做跳转预览。不出现 Strava 授权、同步、解绑类文案（代码现有说明“无需 Strava 授权…”属于否定说明，可以保留）。
2. **个人信息展示规则**（用户已确认，详见 `docs/cloudbase-schema.md`）：

   | 查看者 | 实名 | 手机号 / 紧急联系人 | 昵称 |
   | --- | --- | --- | --- |
   | 本人 | 完整 | 完整 | 显示 |
   | 审核管理员 | 完整 | 完整 | 显示 |
   | 其他骑友 | 不显示 | 不显示 | 只显示昵称 |
   | 后援车司机 | — | 电话公开、完整显示 | — |

   不允许出现 `****` 脱敏。云端仍按原方式加密存储，此规则只决定页面上显示什么。
3. **不恢复深色主题**。媒体区（照片上的文字、无图品牌黑底、票据主栏）使用黑底白字，属于明亮主题内的内容区，不算深色主题。
4. **文案**：面向用户的文字一律用中文口语，不出现“幂等入队”“RESULT / 1”这类技术词。计数写“共 n 场 / 共 n 人”。导航标题与页内标题一致。
