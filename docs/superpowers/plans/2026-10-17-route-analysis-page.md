# 完整路线分析页 PRD（首期）

> 日期：2026-10-17
> 状态：首期实施中；未接入能力以边界状态与 TODO 明示，不得使用模拟结果冒充真实服务。
> 冲突说明：开放 PR #251 正在修改总 PRD `docs/requirements-design.md`，本专题完整承载本次需求，避免平行修改冲突。

## 1. 背景

活动的 Strava 公开路线与 GPX 导入、解析、缓存链路已经存在，`Activity.route` 已能提供路线起终点、距离、升降、海拔范围、预计骑行时间、难度、路线轮廓和海拔剖面。当前活动详情只能展示基础路线信息，骑手缺少一个在出发前理解路线节奏、关键公里点和装备下限的集中页面。

首期新增只读“完整路线分析页”，复用现有活动详情接口与 `Activity.route`，在客户端以确定性纯函数派生分析结果；不改变活动发布契约、CloudBase 集合、云函数、Strava/GPX 处理与缓存链路。

## 2. 目标与非目标

### 2.1 目标

- 从活动详情和已通过报名的骑行凭证进入同一分析页。
- 仅使用 `rideService.getActivity(id)` 返回的 `Activity.route` 作为路线事实源。
- 展示四项总览、路线策略、海拔剖面、关键公里点、最多 6 个主要分段、原生地图、基础装备建议和数据质量说明。
- 地图、关键点列表和海拔剖面有可观察的选中联动；支持复制关键点坐标。
- 对缺失轮廓、缺失剖面、短路线、重复点、非法数值和服务失败诚实降级。
- 375px 宽度可用，触控目标不少于 44px，适配底部安全区与系统字体放大。

### 2.2 非目标

- 不提供路线编辑、GPX 上传、发布或缓存写入。
- 不改变活动发布、读取或报名权限契约，不新增云函数和 npm 运行时依赖。
- 不把关键点推导结果写回活动，不生成虚构村镇、POI、天气或交通结论。
- 不提供实时导航、持续定位、轨迹回放或偏航提醒。
- 首期不承诺 Canvas 任意位置拖动或精确 hit-test；以关键点列表、地图 marker 和分段选择驱动联动。
- 首期不实现路线演示动画；`MapContext.moveAlong` 的兼容性、暂停恢复与失败降级需独立真机验证后再评估。

## 3. 用户故事与用户旅程

### 3.1 用户故事

- 作为报名或关注活动的骑手，我希望出发前快速了解距离、爬升、最高海拔和预计骑行时间，以判断体能要求。
- 作为骑手，我希望看到主爬坡、长下坡和建议休息点所在公里数，以安排补给和节奏。
- 作为骑手，我希望在地图与海拔图之间定位同一个关键点，并复制坐标用于会合或外部地图查询。
- 作为骑手，我希望明确知道哪些结论来自活动路线、哪些是客户端规则推导、哪些实时服务尚未接入。

### 3.2 入口与流程

1. 活动详情的 GPX/路线区域仅在存在可分析路线数据时显示“查看完整路线分析”。
2. 骑行凭证已经持有 `activity`/`activityId`；同样仅在路线可分析时显示“查看路线分析”，不改变报名与凭证主流程。
3. 两个入口统一调用 `wx.navigateTo({ url: '/pages/route-analysis/index?id=<activityId>' })`。
4. 分析页读取 query `id`，调用既有 `rideService.getActivity`；加载中、失败、活动不存在、路线不足分别显示明确状态与返回/重试操作。
5. 用户可选择关键点或分段，观察地图 marker、地图视野、关键点详情和海拔图游标/高亮同步变化；可复制选中点经纬度。

## 4. 页面信息架构

按纵向顺序展示：

1. 标题与预览边界：活动名、路线名/起终点、只读分析说明。
2. 四指标总览：距离、累计爬升、最高海拔、预计骑行时间。
3. 路线策略：由真实距离、爬升、海拔和坡段生成的简短策略摘要。
4. 海拔剖面：Canvas 曲线、关键点锚点、当前选择游标、分段范围高亮；无剖面时显示降级说明。
5. 关键公里点：起点、终点、最高点、主爬坡起点、长下坡入口、1–3 个建议休息点；点击后联动。
6. 主要分段：起步、主爬坡、过渡、长下坡、返程等最多 6 段，显示公里范围、升降、坡度、难度与策略。
7. 地图：原生 `<map>` polyline、关键点 markers、`include-points`；地图下方独立详情卡，避免普通 view 覆盖原生组件。
8. 外部增强能力状态：固定显示“实时天气未接入”“交通事件覆盖待开通”，并说明授权、代理、覆盖与费用前置；不把无结果解释为天气稳定或道路畅通。
9. 基础装备建议：只基于真实距离、爬升和最高海拔，明确“不含实时天气”。
10. 数据来源与质量：展示 `Activity.route` 字段覆盖、关键点/分段为本地规则派生、缺失项与降级影响。

## 5. 数据模型与唯一真实数据源

输入仅为 `Activity.route`：

- 位置：`start`、`end`、`startLocation`、`endLocation`、`routeOutline`、`routeBounds`。
- 指标：`distanceKm`、`elevationM`、`elevationLossM`、`elevationMinM`、`elevationMaxM`、`estimatedMovingTimeSeconds`、`level`。
- 剖面：`elevationProfile`。
- 溯源/增强：`externalRouteUrl` 等既有字段只作来源说明，不作为分析 API。

派生输出：

- `overview`：距离、爬升、下降、海拔范围、最高点、预计时间、难度与质量标记。
- `keyPoints[]`：`id/type/name/km/elevation/lat/lng/source/confidence/note`。
- `segments[]`：`id/type/name/startKm/endKm/ascentM/descentM/gradePercent/difficulty/strategy`。
- `strategySummary[]`、`equipment[]`、`quality[]`。

所有输入先过滤 `NaN`、`Infinity`、越界经纬度与负距离；重复剖面距离保留最后一个有效海拔或稳定合并，排序后再派生。空字段不补模拟值。

## 6. 关键公里点派生规则

### 6.1 通用映射

- 海拔样本按真实 `distanceKm` 归一为公里位置；若样本自身带距离则优先使用，并限制在 `[0, distanceKm]`。
- 将目标公里按总距离比例映射到 `routeOutline` 最近索引；若轮廓缺失，经纬度为空但保留公里与海拔。
- `source` 使用“活动路线”“海拔剖面规则”或“距离规则”；`confidence` 为“高/中/低”，由字段完整度确定。

### 6.2 类型

- 起点/终点：优先采用活动真实 `startLocation`/`endLocation` 名称与 `start`/`end` 坐标；缺名称时只使用“路线起点/路线终点”。
- 最高点：取合法剖面最大海拔；无剖面但有 `elevationMaxM` 时仅显示指标级最高点，不伪造精确公里和坐标。
- 主爬坡起点：在平滑后的相邻样本趋势中寻找累计爬升最大、长度达到总里程合理比例的上升窗口，取窗口起点。
- 长下坡入口：寻找累计下降最大且连续下降趋势占优的窗口，取窗口起点。
- 建议休息点：短路线不强制生成；中长路线按总距离在约 35%/60%/80% 产生 1–3 个候选，并避开起终点及其他关键点的近邻。
- 非起终点无法取得地名时，名称必须是“路线最高点”或“建议休息点 · km XX”；`note` 固定说明“地点名称待接入逆地理编码”，禁止推测村镇或 POI。

去重以公里间距为主；同类点只保留规则得分最高者。所有规则必须确定、可解释，同一输入产生同一输出。

## 7. 主要分段派生规则

1. 清洗并按公里排序海拔样本，计算相邻样本的距离、海拔差与坡度；距离为 0 的重复点不参与坡度计算。
2. 以小窗口平滑趋势，将相邻区间分类为上升、下降、平缓；极短抖动并入前后主趋势。
3. 基于总距离切出候选：前 10%–20% 为“起步”、累计爬升最显著区间为“主爬坡”、累计下降最显著区间为“长下坡”、中间弱趋势为“过渡”、末 15%–25% 为“返程”。
4. 合并同类型相邻候选，删除过短且无显著升降的片段；按公里排序，最多输出 6 段，覆盖范围允许因数据缺失而不连续。
5. 每段升降由样本逐差累计；平均坡度为净高差/水平距离，仅作解释，不替代专业道路坡度。
6. 难度按段长、累计爬升和平均坡度分为轻松/适中/挑战；策略文案来自固定规则，例如稳住踏频、提前补水、下坡控速，不能声称实时路况。
7. 无剖面时仅按距离生成起步/巡航/返程等距离段，升降与坡度标记为不可用；极短路线可只输出 1 段。

## 8. 地图与海拔联动

- 地图绘制清洗后的 `routeOutline` polyline，关键点使用 markers/callout；名称采用真实地点名或诚实的功能名加公里数。
- 初次渲染使用 `include-points` 覆盖全部有效路线坐标；无轮廓则隐藏地图并说明原因。
- 点击关键点列表或 marker：更新 `selectedPointId`，重绘 Canvas 游标/锚点，地图视野包含选中点，地图下方详情卡展示公里、海拔、经纬度、来源、置信度和 note。
- 点击分段：更新 `selectedSegmentId`，Canvas 高亮该公里范围，地图 polyline 使用可观察的选中态，并选中该段附近关键点（若存在）。
- Canvas 首期不宣称支持拖动；图表精确 hit-test 列为后续可用性增强。

## 9. 状态、错误、性能与无障碍

### 9.1 状态与错误

- 复用 `state-view` 展示 loading、请求失败、活动不存在与空路线；错误页提供重试。
- 部分字段缺失时保留可用模块，并在“数据来源与质量”说明缺口；单个 Canvas/map 失败不阻断文本分析。
- 经纬度复制前检查有效性，无坐标时禁用或隐藏复制操作并提示原因。

### 9.2 性能

- 只请求一次既有活动详情，不增加外部网络请求。
- 纯函数线性扫描剖面与轮廓；先清洗、限量显示 marker，避免在 setData 中复制无关活动字段。
- Canvas 适配设备像素比但限制最大像素尺寸；页面显示后再绘制，选择变化仅重绘图表。
- 不引入 npm 运行时依赖，不解析 GPX，不修改缓存。

### 9.3 无障碍与适配

- 375px 与 340px 宽度下卡片不横向溢出，底部包含 `env(safe-area-inset-bottom)`。
- 点击项与按钮至少 88rpx/44px，支持键盘不可用场景下的明确文本反馈；不只用颜色表达选中、难度或状态。
- Canvas 同步提供文字摘要，地图下方提供完整点位信息；原生地图不承载唯一信息。
- 使用全局设计 token，正文/辅助文字达到现有对比度合同。

## 10. 隐私与安全

- 页面只读取公开活动详情已有字段，不请求持续定位，不读取用户当前位置，不采集或上传新数据。
- 坐标复制仅由用户手势触发；不把活动 ID、坐标或路线发送到第三方。
- 外部路线 URL 不自动打开，不在分析页请求第三方内容。
- 不展示 GPX 文件 ID、CloudBase 内部路径、openid、token 或管理字段。
- 活动可见性与报名权限继续由既有服务端控制；客户端入口不构成授权。
