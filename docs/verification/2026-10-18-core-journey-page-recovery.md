# 核心功能旅程与页面恢复验收（2026-10-18）

## 验收范围

本轮覆盖无俱乐部用户发现并加入公开俱乐部、创建俱乐部兜底、俱乐部申请审批后的头像传播、个人资料与活动中的头像展示，以及“我的活动 → 创建活动 / 编辑历史活动”页面恢复链路。

## 根因与修复

| 问题 | 根因 | 修复结论 |
| --- | --- | --- |
| 无俱乐部用户被直接要求创建 | 页面只有“我的创建申请”，没有公开俱乐部发现与加入能力 | 默认展示 approved/active/public_apply 俱乐部；选择后幂等创建 MEMBER，未选择时再展开创建表单 |
| 俱乐部头像缺失 | 审批创建正式俱乐部时只写入 `cover_file_id`，下游读取 `avatar_url` | 新俱乐部显式写入头像字段；旧数据仅在头像字段缺失时回退封面，显式空值保持为空 |
| 私有头像无法稳定展示 | 私有 `cloud://` 地址未在服务端签发临时地址 | Profile 与 Activity Read 批量签发安全 HTTPS；失败时返回空头像，不泄露私有文件 ID |
| 创建活动页空白 | 页面身份初始化异常未被捕获，`loading` 无法收敛 | 捕获异常、展示错误并支持重试，创建参数保持不变 |
| 编辑历史活动空白 | 带活动 ID 的加载异常同样停留加载态 | 重试继续携带原活动 ID，旧请求和已卸载页面不能覆盖新状态 |
| 活动管理列表空白 | 身份初始化位于错误处理之外，模板没有完整加载/错误/未授权状态 | 身份与列表请求统一收敛，加载失败和未授权均有明确状态及重试入口 |

## 核心旅程矩阵

| 旅程 | 正常路径 | 失败恢复与边界 | 验收结果 |
| --- | --- | --- | --- |
| 无俱乐部 → 发现 → 加入 | 仅展示 approved/active/public_apply，选择后创建 MEMBER active | 事务内重读、重复请求幂等、已有管理角色不降级、加入失败保留列表 | 自动化测试通过，生产写入门禁待合并后执行 |
| 无俱乐部 → 创建兜底 | 不选择公开俱乐部时主动展开原创建申请表单 | 无可选俱乐部仍保留创建入口；现有申请状态不被发现列表覆盖 | 自动化测试通过 |
| 俱乐部申请 → 审批 → OWNER | 审批原子创建 club 和 OWNER membership | 重复审批幂等；真实数据库回读头像字段；最终零残留清理 | 自动化测试通过，生产写入门禁待合并后执行 |
| 个人资料读取俱乐部 | active membership + approved/active club 返回摘要 | 旧数据回退 cover；显式空头像不回填；签名失败不泄露 file ID | 自动化测试通过 |
| 俱乐部活动创建与读取 | 服务端生成可信俱乐部身份快照 | 旧 club 兼容；公开读取批量签头像；失败项为空 | 自动化测试通过 |
| 我的活动 → 创建活动 | 身份成功后进入可编辑表单 | 身份失败展示错误；重试后进入创建页 | 自动化测试通过 |
| 我的活动 → 编辑历史活动 | 携带原活动 ID 加载并回填 | 身份失败后重试仍携带 ID；服务读取失败不空白 | 自动化测试通过 |
| 我的活动列表 | 身份与列表成功后展示筛选和操作 | 身份失败、列表失败、未授权、页面卸载及过期请求均收敛 | 自动化测试通过 |

## 测试数据与安全边界

- 生产写入只由 GitHub Actions 中的显式 `CILI_ALLOW_PRODUCTION_SMOKE=club-application-write` 门禁执行。
- 测试使用唯一 run ID 派生隔离记录，覆盖草稿、提交、驳回、修改、重提、批准、club、OWNER membership 与审计记录。
- `finally` 对所有测试集合执行 best-effort 清理，并再次查询确认零残留；任一残留都会阻断部署。
- 日志与断言不输出 OpenID、记录 ID、联系方式、requestId 正文或私有文件 ID。
