## 5. 端到端执行记录

1. 以最新 `origin/main` 为基线创建功能分支，确认无开放 PR 冲突。
2. 对影响面选择器执行 docs、targeted、full、未知路径、未知云函数和 Node Test 回归。
3. 通过本地静态服务器打开 `docs/articles/agile-delivery.html`，在三档视口验证 7 个章节、2 张配图、资源加载、横向溢出与浏览器错误。
4. 执行 Pages 契约、设计契约与 UI sync 严格校验，确认交付中心入口和原型摘要一致。

**执行结论**：本地定向与视觉验收 PASS；全量门禁、PR checks 和合并后部署回读待后续阶段完成。

**未执行或阻塞说明**：当前无代码阻塞。GitHub Actions 定时触发、自动修复 PR 与自动合并只在仓库平台环境具备真实权限；合并后需人工触发一次 `workflow_dispatch` 做平台回读。仓库未配置 `NIGHTLY_PR_TOKEN` 时，夜间任务会安全降级为只创建 PR、不自动合并。

## 7. 风险与回滚

- 剩余风险：GitHub 平台权限、分支保护与 auto-merge 开关只能在真实 Actions 环境最终确认。
- 监控与观察：关注 PR 影响面耗时、每日审计运行时长、去重 Issue、修复 PR 和误回退全量比例。
- 回滚步骤：回滚本次单提交，恢复旧 `ci.yml`，删除每日审计 workflow、选择器脚本与 Pages 文章入口。
- 数据恢复：不适用；不修改业务数据。

## 8. 最终结论

当前实现满足进入全量门禁与 PR 阶段的条件；只有在全量门禁、PR checks、合并后 Pages/main CI 以及一次人工触发的每日全量审计全部通过后，才完成最终验收。
