# 用户权益、内容处置与反馈操作规程

日期：2026-10-21。本文为待审阅的操作规程，不表示收件人员、产品入口或自动任务已就绪。正式生效需负责人接收渠道、产品部署和受控样本验收。

## 受理与处理记录

最小方案采用微信官方“意见反馈”作为站内受理入口，同时提供实际可接收的隐私联系邮箱或电话。开发者在微信公众平台“客服反馈”查看提交内容；打开反馈页不能当作提交成功、后台收件或回复成功。[微信 button feedback 说明](https://developers.weixin.qq.com/miniprogram/dev/component/button.html)

暂不新建自有反馈表、消息系统或私人通讯录。受理记录在私有运营系统保存，公开 Git 只留脱敏计数与验收结果。

| 记录字段                 | 规则                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| 请求编号、类型、受理时间 | 类型区分更正、复制、删除、撤回、举报、申诉和一般问题                                |
| 本人核验状态             | 使用现有可信微信身份或必要的受控核验，不默认要求身份证件或收集完整证件照片          |
| 对象范围                 | 指向本人资料或具体活动/媒体；不要用被举报人的实名或电话当公开编号                   |
| 处理责任角色和进度       | 已受理、核验中、处理中、待本人补充、已完成或说明限制                                |
| 限制与合法保留           | 必须明确依据、字段、用途限制、到期或复查方式；不能笼统说“永久保存”                  |
| 回复及申诉               | 保存实际回复结果和本人可用的申诉方式；误封或误删有复核                              |
| 安全证据                 | 原始反馈可能含个人信息，限制访问；公开摘要不含原文、手机号、令牌、fileID 或私人 URL |

响应和完成期限由负责人承诺并落实；本规程不编造法定或运营“15天/30天”承诺。法律要求便捷受理，拒绝请求须说明理由。[个人信息保护法第五十条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

## 更正、复制与授权撤回

- 本人更正通过既有资料编辑；涉及错误联系人、司机、活动或违规内容，由有权限的管理员核验处理。
- 复制资料由受控人工流程生成本人范围的副本，不包括其他骑友信息；跨用户请求必须拒绝。
- 微信能力授权使用平台设置入口，取消通知以微信当前订阅结果为准，不做虚假的永久关闭开关。
- 微信隐私说明是查看入口，不是自动撤销全部授权；平台“通知开发者删除”的请求要实际接收、登记和处理。
- 公开披露同意撤回后，公开名单和名片须隐藏相应字段；本人和依法必要审核用途另行核对，不因撤回公开图片而自动取消报名。
- Strava 撤销须停止新授权/导入、撤销第三方访问、处理本地 token 和未消费 state；保留已合法发布的活动路线是否适用由用途、授权及权利请求范围判断。

## 资料删除范围

资料删除与账号注销分开命名。首版应清除可删除的本人个人资料和关联私人副本，并说明仍保留的业务关联；不宣称微信身份、所有历史活动和平台审核记录全部注销。

| 数据                                     | 删除或处置要求                                                                                                   |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `profiles`                               | 删除实名、电话、紧急联系人、昵称、性别、头像、背景和历史兼容敏感字段；保留状态与必要身份关联需最小化且明示       |
| `registrations.profile_snapshot`         | 同时清理昵称、掩码、联系人等旧副本；缺 profile 时不能回退旧昵称或联系人                                          |
| 本人活跃报名                             | 首先清晰说明影响；用户可选择按原业务取消。若删除与活动安全职责存在冲突，受理请求并提供受限处理，不能无限期拒绝   |
| `profile_media`、`profile_media_imports` | 精确处理本人个人头像/背景及 staging/canonical，进入既有可重试清理；不能按 owner 一把删掉他上传的俱乐部或活动图片 |
| 活动和俱乐部引用                         | 检查媒体交叉引用；先停止相关展示，再安全处置。不要删除他人或运营主体合法资料                                     |
| Strava token/state                       | 撤销/限制调用与删除补偿；迟到回调、刷新和导入不得恢复已撤回的数据                                                |
| 旧申请、预览、通知与审计                 | 按实际请求范围、必要性、公开状态和保留依据分类处理；通知停止不必要投递，日志不留原值                             |
| 缓存与临时下载地址                       | 本人缓存失效；服务器停止签发，已签发地址有实际有效期限制；删除成功不能保证他人已下载副本自动消失                 |
| 备份                                     | 确认保留周期；恢复必须重放删除/撤回记录，避免将已删资料重新公开或用于报名                                        |

个人资料删掉后不得通过后台读失败、默认同步、旧请求或同一次 OAuth 回调静默重建；再次使用需要明确用户操作和适用同意。

## 删除流程与失败补偿

1. 受理请求并核验本人，明确数据范围、正在进行的业务关系、影响与可用保留依据。
2. 服务端写入持久请求及版本；暂停相关个人信息写入和公开披露。使用可信微信身份，不接受客户端传入 owner、审批结果或 fileID 删除列表。
3. 事务清除/隔离可即时删除的资料和公开回退快照；并发报名、资料更新或上传 finalize 需读取同一删除状态，禁止恢复数据。
4. 为本人个人媒体建立或复用精确清理意图，先核对业务引用和 canonical 归属再删除；与原有 worker 的租约、重试和终态规则一致。
5. 对第三方撤销、历史个人副本、通知和必要保留执行分批任务。外部调用超时先对账，不能以数据库删除替代第三方撤销。
6. 回读服务端、公开名单、管理端、个人中心与云存储，返回“已清除资料/媒体处理中/待处理限制”等真实状态。只有所有适用步骤完成才显示完成。
7. 重试从未完成游标继续；持久记录错误的非敏感分类与进度，失败不返回原始数据库/HTTP 错误。
8. 验证备份恢复后的删除重放；人工受理记录与执行结果对应。保留期未届满或技术暂不能删除时停止其他处理，并告知用户理由与后续措施。

现有 profile-media-cleanup 只识别“资料引用”，尚不能被假定为所有业务媒体跨引用的删除安全证明。首版必须把个人媒体与活动/俱乐部媒体类别分开并检查异常存量引用。

## 内容审核与违规处置

文本方案：在服务器写入昵称、活动公开标题/说明、俱乐部名称/简介等前使用 `security.msgSecCheck` v2。只发送审核所需公开文字及可信微信标识，`pass` 才放行；`risky` 拒绝，`review` 等待核验；超时、配额、权限或畸形响应不可默认为通过。[文本接口](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_msgseccheck.html)

图片方案：使用 `security.mediaCheckAsync` v2 对经过现有格式/归属/内容摘要校验的图片提交检查。成功返回 `trace_id` 只表示已受理，不表示图片通过。待审、违规或失败图片不能用于公开投影、业务发布或分享。[图片接口](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_mediacheckasync.html)

| 阶段        | 必要行为                                                                                                              |
| ----------- | --------------------------------------------------------------------------------------------------------------------- |
| 提交        | 服务端签发可被检查服务器访问的有限时 URL；持久绑定 owner、category、source/canonical ID、摘要和 trace，不记录原始 URL |
| 待审        | 旧合法图片保留，新图不公开；页面明确等待和可重试状态                                                                  |
| 微信回调    | 验证来源签名、解密后的 AppID、事件名、trace、版本、错误码和绑定信息；重放和迟到回调不能覆盖新版本或删除终态           |
| 通过        | 只有有效 `pass` 允许新资产进入原有业务激活事务；客户端不得写审核结果                                                  |
| 需复核/违规 | 保持不可公开，管理员按权限核验、通知本人并提供重提/申诉；平台 risky 不提供任意绕过放行                                |
| 故障        | 保留旧内容，限制重试、排查配额/链接/权限；没有结果不能用超时当通过                                                    |
| 存量        | 正式上线前盘点已展示素材并人工/平台审核、替换或停止展示；不能只验证新增而宣称全量覆盖                                 |

**回调部署限制：**微信当前“云函数接收消息推送”文档明确该模式仅支持客服消息；不能假定任意客户端 event 或普通云调用就是内容审核可信回调。首版采用经过验签的 HTTP 消息接收端，或经实际验证的官方支持能力。回调 token/AESKey 只走受控 Secret，不公开。[消息推送说明](https://developers.weixin.qq.com/miniprogram/dev/framework/server-ability/message-push.html)

违规内容处置应尽快停止展示与传输，保存必要受控记录并按适用规则报告。活动下架复用已存在的 `published → draft` 和报名凭证失效逻辑，不能为删除活动放宽“仅草稿可删”。昵称、图片和俱乐部资料需服务端阻断投影并处理引用及缓存，不能仅隐藏一个按钮。确认的合法保留记录不用于继续展示。[工信部通知第二项第（十）款](https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html)

## 反馈、举报与申诉闭环验收

1. 普通测试成员从设置进入官方意见反馈，本人自愿提交一条无敏感内容的功能问题。
2. 微信公众平台负责人实际看到相同反馈，记录受理、处理、回复或平台允许的结果告知方式。
3. 通过实际隐私联系渠道提出删除或更正请求；确认有人接收、核验、处理和反馈结果。
4. 用合法测试内容验证违规阻断、活动下架、图片隐藏、缓存失效和原链接不再签发。
5. 提出申诉并实际复核；新版合法内容重提不会恢复原违规数据。
6. 保存同版本、角色、时间、环境和脱敏结论；不代用户发反馈，不把打开页面当真实收件。

以上现场动作涉及用户向他人发送内容，应由测试人员本人执行，或在获得针对该发送行为的明确授权后操作。
