## 本轮确认的事实

- 微信公众平台入口可访问，但当前页面为登录页；账号主体类型、认证、备案、已选类目、隐私声明与反馈收件状态均为**未核验**，不是已失败或已通过。
- 当前设置页具备官方隐私说明和安全缓存清理；资料删除、官方意见反馈按钮与统一内容安全检查尚未实现。
- 候选服务类目为“工具 → 预约/报名”，备案服务内容候选为“生活服务 → 工具”。两套分类分别办理；不能用备案服务内容替代小程序服务类目。
- 昵称、头像、可选背景照片存在公开展示；后援车司机姓名和联系电话完整公开。不能在隐私声明里填写“所有资料仅本人可见”或“无公开披露”。
- 微信官方接口映射将 `wx.setClipboardData` 列入剪切板项目。当前源码仅点击复制时写入，不调用 `wx.getClipboardData`。
- 手机号主要由用户手动填写。服务端保留微信动态手机号接口，但本轮运行页面没有 `open-type="getPhoneNumber"` 按钮；后台应按提审包扫描和实际使用核对，不把保留接口写成已运行流程。
- 内容校验现有能力只验证图片类型、摘要、归属和可信登记，不能当作违法违规内容识别。

## 最少需要负责人补齐的信息

1. 登录正确 AppID 的微信公众平台，核验主体类型与证件名称、主体所在地、认证状态、备案状态和现有类目。备案核身、短信核验和承诺书由真实负责人办理。
2. 提供可公开且实际有人接收的隐私/投诉邮箱或电话，以及负责处理微信“客服反馈”的角色。
3. 审阅资料删除、公开披露同意和内容审核设计；确定实际保存期限、受理响应期限与合法保留例外。所有期限必须与实现和受控运营记录一致。

取得这些信息后再定稿隐私附件、办理后台配置、实施产品功能并完成部署与验收。主体证件缺失不影响审阅代码设计；未部署功能不能写成提审版本已具备。
