# CILI CINEMA 小程序适配 · Design Spec

## 本质需求

把用户确认的 `CILI CINEMA · Cinematic Flow v3` 视觉语言套到当前微信小程序，但业务、字段、权限与后端状态机完全沿用现状。设计的目标是让“活动像一场值得赴约的放映”，不是把骑行产品改造成票务或影视产品。

## 受众与场景

- 普通骑友：浏览活动、查看路线、报名、查看行程与出发凭证、维护个人资料。
- 审核管理员：创建/编辑活动、处理报名、签到、维护唯一俱乐部。
- 主要观看距离：10cm 手机；生产验收继续覆盖 340 / 375 / 430px。

## 核心流程

活动列表 → 活动详情/路线分析 → 填写报名 → 候补/待审核/已通过 → 行程/出发凭证 → 取消或重新报名。

管理流程保持：活动列表/编辑 → 发布/审核 → 报名审核/签到 → 俱乐部维护。

## H5 语义到现有能力的映射

| H5 表达 | 小程序落地 | 后端边界 |
| --- | --- | --- |
| FEED / CAL / FILTER | 活动列表、近期/历史、日期 chips、紧凑/沉浸布局 | 只使用现有活动分页与本地分组，不新增“影单”或日历实体 |
| FILM 五幕 | 活动详情的简介、集合、路线、骑友、装备、日程、费用、活动群 | 全部来自现有 `Activity` 字段 |
| CAST | 公开骑友、发布人、后援车司机 | 不新增演员/剧组实体；遵守个人信息展示规则 |
| WAIVER | 报名页已有“我已阅读行前约定”勾选 | 不新增独立协议记录或版本字段 |
| PAY / METHOD / PROCESSING | 删除；费用只作活动说明 | 不新增支付能力，不展示“已支付” |
| GO | 报名状态结果：候补、待审核、已通过 | 沿用现有状态机，不新增首映/入场状态 |
| BOARDING PASS | 文字出发凭证、集合信息、导航、取消报名 | 不显示条码或个人二维码；活动群二维码仍在详情内 |
| ME | 我的资料、行程、设置、俱乐部与管理员入口 | 沿用现有路由和权限 |

## Form 五问

### 活动列表

- 叙事角色：预告片/发现入口。
- 观众距离：10cm；标题必须在 2 行内可读。
- 视觉温度：期待、沉浸，但不神秘到看不懂时间地点。
- 容量：首屏完整展示 1 个主活动的封面、标题、归属、三项路线指标、集合地点与行动入口，后续活动自然滚动；真实分页与空态保留。
- 视觉母题：骑行活动海报 + 章节式影像流；页面身份由微信现有导航承载，不在正文重复绘制导航横幅。

### 活动详情

- 叙事角色：主片与行动决策页。
- 观众距离：10cm 长页；关键指标与报名状态首屏可见。
- 视觉温度：电影感与安全感并存。
- 容量：现有 11 个内容段落按“看懂活动→确认路线→决定报名”重排，不删除真实信息。
- 视觉母题：胶片章节、海拔声轨、路线刻度。

### 报名与凭证

- 叙事角色：从承诺到出发。
- 观众距离：10cm；错误、隐私和状态信息优先。
- 视觉温度：克制、可信，不做支付或娱乐化误导。
- 容量：保留现有资料、集合方式、经验、备注、行前约定与完整度门槛。
- 视觉母题：片场通告单与出发通行证，但内容仍是报名/凭证。

### 管理端

- 叙事角色：片场调度台。
- 观众距离：10cm 高密度长表单。
- 视觉温度：冷静、明确、可恢复。
- 容量：所有现有字段和上传/路线状态完整保留。
- 视觉母题：通告单、场记状态与可核对的数据行。

## 输出与初稿范围

- 三个方向统一使用 1800 × 1200 展示板。
- 每个方向展示 5 个代表屏：活动、详情、报名、凭证、审核。
- 方向确认前不修改生产小程序代码。
- 选定后再扩展到 17 路由，并同步 Pages 原型、DOM 契约、三宽度证据和 UI digest。

## A · 一镜到底动效系统

- 导航去重：微信原生或现有自定义导航只出现一次，正文不再插入场记横幅、页码或胶片虚线；释放的高度用于首屏业务信息，不另造替代性顶栏。
- 标题显影：主标题由轻微虚化与 8px 下移回到清晰位置，560ms 完成；双行标题从 `120ms / 340ms` 开始错峰，不逐字生成大量节点。
- 活动卡标题：首批可见活动按 120ms 顺序错峰，仍以整行文字为单位，避免长标题逐字节点拖慢小程序。
- 影像开场：活动、个人与俱乐部 Hero 只做一次 1.025 → 1 的轻推近回落，不循环、不自动播放音频。
- 暗面入场：表单、凭证和管理内容整体短距离上移，最多只对首批两个章节追加 40ms 错峰，不对长页所有卡片持续施加动画。
- 滚动边缘：Pages 根据真实滚动位置显示顶部/底部渐隐；小程序以 18px 固定渐隐保护滚动边界，全部 `pointer-events: none`，不劫持滚动。
- 触控反馈：按下只调整 1px 位移与透明度，150–200ms 内完成；Chevron 另以 100ms 做 2px 横向反馈，不改变页面布局。
- 页面切换：Pages 每次切换路由重新创建画面并重播入场；小程序依赖原生页面创建周期播放一次，不循环。
- Web Pages 遵守 `prefers-reduced-motion`，关闭动画与过渡时直接呈现最终可读状态；小程序动效不阻塞数据加载、滚动或点击。

所有颜色、时长、延迟、位移与 easing 统一由 [theme-tokens.md](theme-tokens.md) 管理。页面级样式不得新增硬编码主题值；Logo 红、UI 焦点红和可承载白字的行动红必须保持边界。

## 17 路由连续叙事

01 活动 → 02 活动详情 → 03 填写报名 → 04 出发凭证 → 05 我的行程 → 06 路线分析 → 07 我的 → 08 编辑资料 → 09 设置 → 10 俱乐部中心 → 11 活动管理 → 12 编辑活动 → 13 报名审核 → 14 审核详情 → 15 俱乐部管理 → 16 俱乐部资料 → 17 历史名片兼容入口。

系统导航、滚动边界、原生 TabBar 与 17 条正式路由正文全部统一为电影暗色。画布、卡片和抬升层分别使用 `#0B0A08`、`#151310`、`#211D19`；正文使用暖白，次级信息使用暖灰，表单与管理页不再回到暖白纸面。路由顺序只用于设计核对，不在界面显示场次页码，也不改变任何路由、权限、数据字段、接口、云函数或状态机。

## 2026-10-28 动效验收

- 标准手机外壳：Pages 实测 `390 × 844`；小程序模拟器保持设备原生竖屏，不绘制伪手机边框。
- 时序检查：Pages 与小程序双行标题分别从 `120ms`、`340ms` 开始，单行过渡 `520ms`；活动卡标题按 `120ms` 递进。
- 小程序：全局 WXSS 编译通过，正式项目整包刷新后活动与设置两类页面取证通过，Console / Network 错误筛选为空；WXML 本轮未修改，沿用上一轮 17/17 编译基线。
- Pages：16 个可视页面在 340 / 375 / 430px 三档宽度全部通过，无横向溢出、遮挡、无效小触控目标或 Console 错误。
- 仓库门禁：`check:ui-sync -- --strict`、`check:governance` 与全量 `validate` 通过；87 个测试文件、1295 项 Vitest，主包 442566 字节。
- 证据边界：以上是本地 Pages 与模拟器证据，不替代 iOS / Android 物理真机、普通成员完整写链路或目标云环境回读。
