CILI PRODUCT DESIGN SYSTEM

让每一屏都能在骑行现场被快速理解

此里的完整 UI 规范不是一套装饰模板，而是一份可执行契约：统一路线事实、操作优先级、沸点视觉语言和小程序 / Pages 双端门禁。

做设计时，按这个顺序决定
  1. 任务能否顺利完成
  2. 数据是否一致可信
  3. 移动与户外场景是否可读
  4. 品牌是否保持统一
  5. 双端是否可以验证
01

MASTER SYSTEM

颜色各司其职，不让视觉噪声冒充层级

暖米白承载长屏，墨黑建立信息重心，深行动红负责真正的主要操作，路线红只做品牌与轨迹强调。

暖米白画布--color-bg · #fbf5ea
墨黑信息块--color-text · #211f1c
深行动红--color-action · #c0321f
品牌与路线红--color-brand · #e13b2b
02

PRODUCT PRINCIPLES

信息密度来自组织，不来自更小的字

骑行场景强调移动、阳光、弱网和单手操作。每条规则都服务于快速判断和可靠恢复。

01

唯一主行动

每个视口只保留一个真正的主要操作，次要操作可发现但不争夺注意力。

02

路线事实一致

地图、海拔、海报和详情读取同一份路线事实，里程与地名不在页面中重复计算。

03

失败可以恢复

图片失败不留空白，表单失败不清空输入，错误文案直接说明下一步。

03

PAGE OVERRIDES

统一品牌，不统一成同一种页面

Master System 定义品牌和组件不变量；页面 Overrides 只调整内容顺序、密度和局部表现。

活动详情

先决定是否参加

路线摘要、组织者、报名状态和固定主操作优先；更多分析通过明确入口渐进展开。

完整路线分析

允许高密度，但不允许失去路线

地图和海拔联动，坡顶、补给、卫生间与天气分层显示；不强行套普通详情卡片密度。

报名与资料编辑

输入不丢，错误可继续

单列字段、标签常驻、图片上传进度可见；失败后保留已有内容并给重试路径。

骑行名片

人物优先，数据有节奏

头像、姓名和骑行身份形成第一层，里程、爬升与活动数据放大，单位降低一级。

04

ANTI-PATTERNS

这些不是“个人喜好”，而是交付阻断项

  • 蓝紫 SaaS 渐变、玻璃拟态覆盖沸点主题
  • 通过缩小文字和触控区解决高密度
  • 图片、地图或弹层遮挡固定主操作
  • 只用颜色表达报名、审核和异常状态
  • 活动详情与完整分析给出不同路线事实
  • 失败后留下空白图片或清空表单
  • 把第三方 Web 组件直接翻译进小程序
  • 展示未接入能力、接口名或调试技术词
05

DESIGN INTELLIGENCE

先推理，再画页面；先做切片，再扩展全页

外部设计资料只参与推理，此里 Master System 决定最终答案。每次设计必须留下可复查的决策和证据。

01 INTENT用户与唯一任务
02 CONTENT事实、状态与动作
03 MAPPINGToken 与组件复用
04 OVERRIDE允许偏离的维度
05 RISKS反模式与边界
06 EVIDENCE截图、测试与回读
06

QUALITY GATES

设计必须能被代码和证据共同验证

CONTRACT

Token 与对比度

双端变量同名同值，文字、按钮和状态满足机器可算门槛。

STATES

完整状态矩阵

正常、空、加载、失败、禁用、长文案和窄屏均有证据。

JOURNEY

真实任务旅程

以报名、审核、路线确认和资料保存为验收路径，不只看静态首屏。

DEPLOY

双端部署回读

PR checks、Pages、CloudBase 和微信开发版按真实变更范围验证。

THE RULE OF CILI

外部方法提供设计推理，此里设计系统决定最终答案。

完整可执行规则见仓库根目录 DESIGN.md；数值事实见 design-contract.json；每次 UI 交付按 ui-design-checklist.md 逐项验收。
